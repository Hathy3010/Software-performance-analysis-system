# 07 — Database Schema

## Overview

The database is **PostgreSQL 16**. Schema is bootstrapped by `infra/db/schema.sql` on first container start, then tracked with Alembic for future migrations.

All tables use:
- `UUID` primary keys (generated by `uuid_generate_v4()`)
- `TIMESTAMPTZ` for all datetime columns (timezone-aware)
- `fn_set_updated_at()` trigger for automatic `updated_at` management
- `JSONB` for flexible metadata and labels

## Table Reference

### `users`

Stores authentication credentials and role assignments.

| Column | Type | Notes |
|---|---|---|
| `id` | UUID PK | `uuid_generate_v4()` |
| `email` | VARCHAR(255) UNIQUE | Validated by regex CHECK constraint |
| `username` | VARCHAR(100) UNIQUE | Display name |
| `hashed_password` | TEXT | bcrypt hash |
| `full_name` | VARCHAR(255) | Optional |
| `role` | `user_role` ENUM | `admin`, `analyst`, `viewer` |
| `is_active` | BOOLEAN | Soft-disable without deletion |
| `last_login_at` | TIMESTAMPTZ | Updated by auth router on login |
| `created_at` | TIMESTAMPTZ | Server default NOW() |
| `updated_at` | TIMESTAMPTZ | Auto-updated by trigger |

Indexes: `role`, `is_active`

---

### `services`

Registry of all monitored microservices.

| Column | Type | Notes |
|---|---|---|
| `id` | UUID PK | |
| `name` | VARCHAR(100) UNIQUE | Must match Prometheus `job=` label |
| `display_name` | VARCHAR(255) | Human-readable label |
| `status` | `service_status` ENUM | `healthy`, `degraded`, `down`, `unknown` |
| `prometheus_job` | VARCHAR(100) | Explicit Prometheus job name (may differ from `name`) |
| `namespace` | VARCHAR(100) | Logical grouping (e.g. `prod`, `staging`) |
| `team` | VARCHAR(100) | Owning team |
| `tags` | JSONB | Array of string tags |
| `metadata` | JSONB | Arbitrary key-value pairs |
| `last_seen_at` | TIMESTAMPTZ | Updated when AI engine processes the service |

Indexes: `status`, `namespace`, `team`, `prometheus_job`, GIN on `tags`

---

### `incidents`

Operational incidents. The `duration_seconds` column is computed by PostgreSQL automatically.

| Column | Type | Notes |
|---|---|---|
| `id` | UUID PK | |
| `title` | VARCHAR(500) | Required |
| `severity` | `alert_severity` ENUM | `critical`, `high`, `medium`, `low`, `info` |
| `status` | `incident_status` ENUM | `open`, `investigating`, `resolved`, `closed` |
| `service_id` | UUID FK → services | SET NULL on service deletion |
| `assigned_to` | UUID FK → users | SET NULL on user deletion |
| `created_by` | UUID FK → users | SET NULL on user deletion |
| `started_at` | TIMESTAMPTZ | Default NOW() |
| `resolved_at` | TIMESTAMPTZ | Set by POST /incidents/{id}/resolve |
| `duration_seconds` | INTEGER **GENERATED ALWAYS AS STORED** | `EXTRACT(EPOCH FROM (COALESCE(resolved_at, NOW()) - started_at))` |
| `alert_count` | INTEGER | Maintained by application layer |
| `tags` | JSONB | |
| `metadata` | JSONB | |

Constraints: `resolved_at >= started_at`, `closed_at` requires `resolved_at`

**Important:** Never write to `duration_seconds` directly — PostgreSQL will reject it. It is automatically recomputed whenever `resolved_at` changes.

### `alerts`

Individual alert firings, linked to a service and optionally an incident.

| Column | Type | Notes |
|---|---|---|
| `id` | UUID PK | |
| `service_id` | UUID FK → services | SET NULL on deletion |
| `incident_id` | UUID FK → incidents | SET NULL on deletion |
| `alert_name` | VARCHAR(255) | Prometheus alert name (e.g. `HighP99Latency`) |
| `severity` | `alert_severity` ENUM | |
| `status` | `alert_status` ENUM | `firing`, `resolved`, `acknowledged`, `suppressed` |
| `fingerprint` | VARCHAR(64) UNIQUE | SHA-256 for deduplication (matches Prometheus fingerprint) |
| `metric_name` | VARCHAR(255) | The metric that triggered this alert |
| `metric_value` | DOUBLE PRECISION | Detected value at time of firing |
| `threshold_value` | DOUBLE PRECISION | Configured threshold |
| `labels` | JSONB | Prometheus label set |
| `annotations` | JSONB | Prometheus annotations |
| `fired_at` | TIMESTAMPTZ | Default NOW() |
| `resolved_at` | TIMESTAMPTZ | |
| `acknowledged_by` | UUID FK → users | |

Indexes: `service_id`, `incident_id`, `severity`, `status`, `fired_at`, GIN on `labels`  
Partial index: `WHERE status = 'firing'` for fast active-alert queries

### `anomaly_results`

Persisted output from the AI engine's anomaly detection step.

| Column | Type | Notes |
|---|---|---|
| `id` | UUID PK | |
| `service_id` | UUID FK → services CASCADE | |
| `alert_id` | UUID FK → alerts | SET NULL on deletion |
| `anomaly_type` | `anomaly_type` ENUM | `spike`, `drop`, `trend_shift`, `pattern_change`, `threshold_breach` |
| `metric_name` | VARCHAR(255) | Primary metric that triggered detection |
| `anomaly_score` | DOUBLE PRECISION | 0.0–1.0 CHECK constraint |
| `confidence` | DOUBLE PRECISION | 0.0–1.0 CHECK constraint |
| `is_confirmed` | BOOLEAN | NULL = pending, TRUE = confirmed, FALSE = dismissed |
| `model_name` | VARCHAR(100) | `IsolationForest` or `threshold_fallback` |
| `baseline_mean` | DOUBLE PRECISION | Mean of rolling buffer |
| `baseline_std` | DOUBLE PRECISION | Std of rolling buffer |
| `raw_data_snapshot` | JSONB | Feature vector snapshot |
| `detected_at` | TIMESTAMPTZ | |

Composite index: `(service_id, metric_name, detected_at DESC)` for time-series queries

### `rca_results`

Root cause analysis output, optionally linked to an incident and anomaly.

| Column | Type | Notes |
|---|---|---|
| `id` | UUID PK | |
| `incident_id` | UUID FK → incidents CASCADE | |
| `anomaly_id` | UUID FK → anomaly_results | |
| `service_id` | UUID FK → services CASCADE | The service that was anomalous |
| `root_cause_service_id` | UUID FK → services | The service identified as root cause |
| `summary` | TEXT | One-line summary for display |
| `root_cause` | TEXT | Detailed explanation |
| `contributing_factors` | JSONB | `[{factor, weight, evidence}]` |

| `recommendations` | JSONB | `[{action, priority, owner}]` |
| `confidence_score` | DOUBLE PRECISION | 0.0–1.0 |
| `status` | `rca_status` ENUM | `pending`, `processing`, `completed`, `failed` |
| `analysis_duration_ms` | INTEGER | How long the analysis took |

|---|---|---|

### `audit_logs`

| Column | Type | Notes |

| `action` | `audit_action` ENUM | `create`, `update`, `delete`, `login`, `logout`, `acknowledge`, `resolve`, `assign`, `escalate` |
| `resource_type` | VARCHAR(100) | `incident`, `alert`, `user`, etc. |
| `resource_id` | UUID | The affected record |
| `old_values` | JSONB | State before change |
| `new_values` | JSONB | State after change |
| `ip_address` | INET | |
| `request_id` | VARCHAR(100) | OTel trace ID for correlation |

## Migration Workflow

```bash
# After changing a model file:
make backend-shell
alembic revision --autogenerate -m "add_field_X"
alembic upgrade head

# Check current revision:
alembic current

# Roll back:
alembic downgrade -1
```
